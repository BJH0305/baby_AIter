# RUN.md — Codex 자동 진행 지시서

> 사람(배준희)이 "docs/RUN.md 읽고 진행해"라고 하면, Codex는 이 파일대로 **멈출 조건이 나올 때까지 스스로 계속 진행**한다.
> 판단이 애매한 것은 절대 혼자 정하지 않고, 아래 "허락 요청 형식"으로 물어본 뒤 답을 받고 이어서 진행한다.

## 1. 시작할 때 (매번)
1. `AGENTS.md`, `docs/TEAM.md`, `docs/idea-brief.md`를 읽는다 (이미 읽었으면 바뀐 부분만).
2. `docs/REVIEW.md`의 `[ ]` 항목을 확인한다.
3. `docs/TASKS.md`에서 첫 번째 `[ ]` 작업을 찾는다.
4. 사람에게 한 줄로 알린다: `▶ 시작: [REVIEW n개, 다음 작업 T번호]`

## 2. 반복 (자동)
아래를 멈출 조건이 나올 때까지 반복한다.
1. **REVIEW 먼저**: `docs/REVIEW.md`에 `[ ]` 항목이 있으면 위에서부터 처리한다.
2. **다음 TASK**: 없으면 `docs/TASKS.md`의 첫 번째 `[ ]` 작업을 처리한다.
3. **작업 하나 끝날 때마다**
   - 직접 확인: 콘솔 에러 없음, 해당 화면이 열리고 버튼이 동작함 (가능한 범위에서)
   - `TASKS.md`(또는 `REVIEW.md`) 해당 줄 `[x]` + 바로 아래 `  - 메모: 바뀐 파일 / 확인 방법 / 남은 문제`
   - `git add -A` → `git commit -m "T번호: 요약"` (push는 하지 않는다)
   - 사람에게 보고: `✔ T번호 완료 — 바뀐 것 1줄 / 확인 방법 1줄`
4. 바로 다음 작업으로 넘어간다. 사람의 "계속"을 기다리지 않는다.

## 3. 허락받아야 하는 것 (멈추고 물어본다)
아래 중 하나라도 해당하면 **구현하기 전에 멈추고** 허락 요청을 보낸다.
- TASKS·idea-brief·AGENTS에 적혀 있지 않은 **화면, 기능, 버튼, 데이터 필드**를 새로 만들어야 할 때
- 작업 설명이 두 가지 이상으로 해석될 때 (예: 화면 배치, 문구, 흐름 순서)
- `js/knowledge.js` 카드 **내용**(원인, 지도법, 출처)을 바꾸거나 새 지도법 문장을 지어내야 할 때 (형식 수정은 가능)
- mock 답변에 카드에 없는 육아 정보가 필요할 때
- 파일 구조 변경, 파일 삭제, 새 라이브러리·CDN 추가
- 기존에 동작하던 기능을 크게 고쳐야 할 때 (예: 저장 구조 변경)
- 같은 문제를 2번 고쳐도 해결이 안 될 때
- `🛑 사람 확인` 표시 작업에 도착했을 때
- API 키, 외부 서비스 가입·배포, `git push`, 되돌리기(`git reset`, `git restore`)가 필요할 때

## 4. 허락 요청 형식 (이 형식 그대로)
```
⏸ 확인 필요 (T번호)
상황: [무엇 때문에 멈췄는지 1줄]
선택지:
  A. [방법] — 장점/단점
  B. [방법] — 장점/단점
추천: [A 또는 B]와 이유 1줄
→ A/B 중 답해 주세요. (다른 생각이 있으면 그대로 말해 주세요)
```
- 같은 내용을 `TASKS.md` 맨 아래 `## 질문`에도 적는다.
- 답을 받으면 결정을 `## 질문`의 해당 항목 아래 `  - 결정: ...`으로 남기고 이어서 진행한다.
- 답을 기다리는 동안 **다른 작업으로 넘어가지 않는다.**

## 5. 혼자 정해도 되는 것 (묻지 않는다)
- 변수·함수 이름, 주석, 코드 정리
- 기존 컴포넌트 클래스를 이용한 세부 배치(간격, 정렬)
- 콘솔 에러, 오타, 명백한 버그 수정
- TASKS 설명에 이미 적힌 범위 안의 구현 방법

## 6. 멈출 때 (자동 진행 끝)
아래 중 하나면 멈추고 요약을 보낸다.
- 3번 "허락받아야 하는 것"이 나왔을 때 (4번 형식으로)
- `TASKS.md`의 `[ ]` 작업이 모두 끝났을 때
- 사람이 "멈춰"라고 했을 때

멈출 때 요약 형식:
```
■ 정지 — 완료: T1~T3 / 다음: T4 / 이유: [허락 필요 | 전부 완료 | 요청]
확인해 볼 것: [index.html에서 무엇을 눌러 보면 되는지 1~2줄]
```

## 7. 절대 하지 않는 것
- 허락 없이 범위 밖 기능 추가, 육아 정보 지어내기, 진단 표현 사용
- API 키를 코드·커밋·로그에 남기기
- `guide/` 수정, `TASKS.md`·`REVIEW.md`의 작업 설명 문장 수정 (체크·메모·질문만)
- 사람 허락 없이 push
