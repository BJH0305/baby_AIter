# TEAM.md — 베이비 AI터 팀 작업 규칙 (사람 + Codex + Claude 공통)

> 팀원 모두와 Codex가 참고하는 한 장짜리 규칙이다. 바뀌면 배준희가 이 파일을 고친다.
> 서비스 한 줄: 친구·동생을 깨무는 만 2~3세 아이의 부모가, 공공기관 자료에 근거한 연령별 지도법을 받아 적용하고 결과에 따라 조정하도록 돕는 AI 상담 웹.

## 1. 역할
| 누구 | 맡는 일 | 만지는 파일 |
| --- | --- | --- |
| 배준희 (컴퓨터공학, 팀장) | 구현 총괄, Codex·Claude 운전, Git·배포, 시연 영상 | 코드 전체, `docs/TASKS.md` 진행 |
| 한서희 (유아교육) | 지식 카드 자료 조사·검수, 지도법 내용 감수, 꾸럼e 기록, 화면 문구 검토 | `js/knowledge.js`(카드 내용), 꾸럼e |
| 이성찬 (전자공학) | 디자인 레퍼런스 수집, 발표 PDF, 확장 구조(기기·데이터 흐름) 설계, 제출 | `docs/design-ref/`(캡처), 발표 자료 |
| Codex | `docs/TASKS.md` 순서대로 구현, 작업마다 체크·메모·커밋 | 코드, `TASKS.md` 체크·메모 |
| Claude | 명세·작업 목록 작성, 코드 검토, 프롬프트·카드 형식 관리, 꾸럼e·발표 문장 | `TASKS.md`(작업 추가), `REVIEW.md`, `docs/*.md` |
(역할은 상황에 따라 바꿔도 된다. 바꾸면 이 표를 고친다)

## 2. 전체 흐름
```
[한서희] 자료 조사·검수 ─→ js/knowledge.js (근거 카드)
[이성찬] 레퍼런스 캡처 ──→ docs/design-ref/ (디자인)
                              │
[Claude] TASKS.md 작성 ───→ [Codex] 구현 → TASKS 체크·커밋
     ↑                                        │
     └──── [Claude] 검토 → REVIEW.md ←────────┘
                              │
[배준희] 시연 확인 → GitHub push → 배포 링크 단톡 공유
```

## 3. 소통 규칙
- **단톡방**: 진행 공유, 질문, 파일 전달(캡처·자료). 중요한 결정은 단톡에 한 줄로 남긴다 ("결정: ○○로 간다")
- **매 정각**: 각자 지난 1시간 한 일 1줄을 단톡에 → 한서희가 꾸럼e에 기록 (수행 점수)
- **막히면 15분 규칙**: 15분 넘게 막히면 바로 단톡에 공유
- **Codex에게 말하는 사람은 배준희 한 명**. 다른 팀원이 바꾸고 싶은 건 단톡으로 배준희에게
- 코드 파일은 배준희(=Codex)만 수정한다. 팀원은 GitHub 웹에서 `docs/sources/cards.md`(카드)와 `docs/design-ref/`(캡처)에만 올린다 → 방법은 **`CONTRIBUTING.md`**

## 4. Codex ↔ Claude 협업 규칙 (파일로 통신)
| 파일 | 누가 쓰나 | 내용 |
| --- | --- | --- |
| `docs/TASKS.md` | Claude가 작업 추가, Codex가 체크·메모 | 구현할 작업 순서 |
| `docs/REVIEW.md` | Claude가 수정 요청, Codex가 처리 후 체크 | 검토 결과 |
| `docs/idea-brief.md` | Claude (팀 결정 반영) | 기획 기준 |
| `AGENTS.md` | Claude | Codex 규칙 |
| `docs/RUN.md` | Claude | Codex 자동 진행·허락 요청 규칙 |
- 배준희가 Codex에게 "TASKS 진행해" → Codex는 REVIEW의 [ ] 먼저, 그다음 TASKS의 [ ] 하나 처리
- 배준희가 Claude에게 "검토해" → Claude가 바뀐 코드를 읽고 REVIEW·TASKS 갱신
- `🛑 사람 확인` 작업은 Codex가 멈추고 배준희에게 알린다

## 6. 지식 카드 규칙 (한서희)
- 출처는 공공기관·공신력 있는 기관 자료만 (중앙·지역 육아종합지원센터, 육아정책연구소, 보건복지부, 교육부, 질병관리청 등). 블로그·맘카페 금지
- 카드마다 `source`(기관명 - 제목 - URL)와 `evidence`(페이지에 실제로 있는 문장)를 넣는다
- 링크를 직접 열어 내용이 맞으면 `verified: true`로 바꾼다. 확인 못 했으면 false 그대로
- 진단·치료 표현은 쓰지 않는다 ("ADHD일 수 있음" 같은 문장 금지)
- 아이 실명·사진은 어디에도 넣지 않는다 (예시 아이: 도윤, 가명)

## 7. 디자인 레퍼런스 규칙 (이성찬)
- banani.co/references (무료). 전체 분위기는 **Calm** 한 앱으로 통일, 화면 구성은 ChatGPT(답변), Duolingo/Things 3(기록) 참고
- 파일 이름: `ref_home.png`, `ref_input.png`, `ref_result.png`, `ref_log.png` → 단톡에 올리면 배준희가 `docs/design-ref/`에 넣음
- 캡처는 참고용. 발표 자료에 그대로 넣지 않는다

## 8. Git·업데이트 규칙 (배준희·Codex·Claude)
- 작업 하나 끝날 때마다: TASKS 체크·메모 → `docs/CHANGELOG.md` 한 줄 → `README.md` 진행 현황 갱신 → 커밋(`T번호: 요약`) → pull → push (Codex 자동)
- Claude는 검토·문서 수정 때마다 CHANGELOG에 한 줄 추가
- 팀원 업로드도 커밋 메시지 규칙(`자료:`/`레퍼런스:`)을 지키면 GitHub 기록이 곧 협업 증거가 된다 (수행 점수)
- 21:30 동결 이후에는 새 기능을 넣지 않는다
- 망가지면 마지막 잘 되던 커밋으로 되돌린다 (Codex에게 "직전 커밋으로 되돌려줘")
