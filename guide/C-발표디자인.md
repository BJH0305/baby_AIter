# C. 발표·디자인 플레이북 (발표 25점 책임)

> 목표: 5분 발표 PDF + 리허설 2회 + 화면 검수.
> 발표자료 PDF는 **필수 제출물**이다 (OT: 팀 결과물 = 웹페이지 1개 + 발표자료 PDF 1개, 31일 09:30 취합).
> 웹 시연은 발표 안의 90초 구간이고, 슬라이드가 문제·근거·효과를 설명한다.

## 왜 이렇게 하나 (점수 전략)
- 발표 25점(자료 완성도, 논리성, 설득력)은 두 최우수상(총장상) 모두에 들어간다
- 심사위원은 10팀을 연달아 본다. 첫 30초(문제 장면 + 숫자)에서 기억에 남아야 한다
- 웹 화면과 슬라이드의 색·글꼴이 같으면 "완성된 서비스"로 보인다
- 화면 검수는 구현 점수(서비스 완성도)에도 들어간다. AI티 나는 화면은 C가 걸러낸다

## 오늘 밤
- [ ] 발표 도구 정하기: Google Slides / PowerPoint / Canva 중 익숙한 것 (마지막에 PDF로 내보내기 가능한지 확인)
- [ ] Mobbin(mobbin.com)에서 참고할 앱 화면 2~3개 골라 두기

## 슬라이드 규칙 (웹과 같은 디자인으로)
- 색과 글꼴은 웹 화면(`css/styles.css` 토큰)과 맞춘다. 같은 포인트 색, 같은 제목 글꼴
- 한 장에 문장 1~2줄 + 그림 1개. 글로 채우지 않는다
- 화면 캡처는 폰 비율로: 크롬 F12 → 기기 모드(iPhone 12 Pro) → Ctrl+Shift+P → "Capture screenshot"
- 시연 영상은 PDF 안에서 재생이 안 될 수 있다. **링크 + QR코드**로 넣고 캡처 2~3장을 순서대로 붙인다

## 구성 (5분)
| # | 슬라이드 | 시간 |
| --- | --- | --- |
| 1 | 표지: 서비스 이름, 한 줄 소개, 팀원 이름·학과 | 10초 |
| 2 | 문제: 한 사람의 장면 + 근거 숫자 1개 | 40초 |
| 3 | 기존 방법의 한계 | 30초 |
| 4 | 해결: 한 문장 정의 + 핵심 기능 3개 | 30초 |
| 5 | 전공 융합: 팀원별 관점 | 30초 |
| 6 | 시연 (라이브 또는 영상) | 90초 |
| 7 | 개발 과정: 꾸럼e 기록·커밋 타임라인 캡처, 역할 | 20초 |
| 8 | 기대 효과·확장 (숫자) | 30초 |
| 9 | 마무리: 한 줄 메시지 + 시연 QR | 10초 |

`docs/spec.md` 10번에 슬라이드별 핵심 문장이 있고, `guide/prompts.md` 7번으로 대본 초안을 뽑을 수 있다.

## 화면 검수 체크 (DESIGN.md 7번 요약)
- 그라데이션·이모지·보라색·그림자 없음
- 포인트 색은 버튼·선택 상태에만
- 홍보 문구 없음, 버튼은 동사
- 예시 데이터가 실제 지명·날짜·숫자
- 눌러 보이는 건 전부 동작
- 폰 폭에서 가로 스크롤 없음

## 질의응답 담당
- 기대 효과, 확장 계획, 수익·지속 방법
- 질문이 오면 누가 답할지 C가 바로 넘겨준다 ("기술 부분은 OO이 답하겠습니다")
