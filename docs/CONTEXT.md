## 2. 무엇을 내야 하나
- 웹페이지 1개 (작동 영상 또는 캡처본으로도 제출)

- 발표 5분 + 질의 3분. 발표 안에 90초 시연

## 3. 어떻게 채점되나 (심사위원 3인, 각 25점)
| 항목 | 보는 것 | 너(Codex)가 기여할 점 |
| --- | --- | --- |
| 기획 | 독창성, 실현 가능성, 사회적 유용성, **전공 융합** | 아이디어 평가, 근거가 약한 부분 지적, 팀원 전공이 들어갈 지점 제안 |
| 수행 | **꾸럼e 기록 성실성**, 협업 기여도, 과정 주도성 | 커밋 단위로 작게 작업, 진행 기록 초안 작성 |
| 구현 | 서비스 완성도, 아이디어 실현도, 코딩 완성도 | 시연이 끊기지 않는 코드, 빈 상태·예외 처리 |
| 발표 | 자료 완성도, 논리성, 설득력 | 대본, 예상 질문과 답 |

- 총장상(최우수상) 2팀: 탐구형 = 기획+수행+발표 / 실현형 = 기획+구현+발표
- 우리 목표: **총장상**. 기획·발표는 기본, 구현에서 "핵심 기능 하나는 진짜로 동작"으로 실현형을 노린다

## 4. 원칙 (판단이 애매하면 이걸로 결정)
1. **시연이 끊기지 않는 것**이 기능 개수보다 중요하다. 기능은 핵심 3개 + 보조 최대 2개
2. 서버 없이 브라우저만으로 동작 (localStorage). 실서비스 단계는 발표에서 말로 설명
3. AI 기능은 LLM API를 실제로 호출하되(키는 서버 함수에 숨김), 실패해도 미리 만든 답변으로 시연이 이어지게 한다 (AGENTS.md 기술 스택 참고)
4. 지어낸 통계·출처·인터뷰 결과 금지. 모르면 "[확인 필요]"
5. "AI가 만든 티"가 나는 디자인 금지 (DESIGN.md)
6. 심사위원이 "이 코드 설명해 보세요" 할 수 있다. 사람이 설명할 수 있게 단순하게, 주석 달기
